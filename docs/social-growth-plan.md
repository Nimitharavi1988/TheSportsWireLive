# Facebook Growth Plan — Draft for Approval

Status: **draft, not yet implemented in strategy — code capability built, nothing posted live.**
Scope: how approved articles get turned into Facebook Page posts, and how we grow followers/reach with them.

## Goal

Grow Page followers and organic reach using the articles already flowing through the
existing pipeline (football-data.org scores/previews, RSS news, trending-keyword scoring),
without buying reach or reposting other people's content.

## Content strategy: original, not scraped

"Viral" framing was part of the original ask, so to be explicit about the choice made here:
this plan does **not** rewrite or repost other creators' viral posts. That risks copyright
claims and Meta's reused-content penalties, and it's not something I'll help automate.

Instead, "viral-shaped" content comes from **being first and clear on things people are
already searching for**:

- `trendingScore` (see [`trending.ts`](../src/lib/ingestion/trending.ts)) already cross-references
  Google Trends' daily trending searches against article titles — articles matching a trending
  keyword score higher and sort first on the homepage. The same score should decide **posting
  priority**: trending-matched articles get posted to Facebook immediately on approval;
  everything else can be batched (see Cadence below).
- Captions are generated from our own title/summary (see `composeCaption` in
  [`facebook.ts`](../src/lib/social/facebook.ts)) — original text every time, not copied from anywhere.

## Rich content: auto-generated image cards

Facebook posts with an image consistently outperform text-only posts, but sourcing real
player/team photos raises licensing questions (most sports photography is copyrighted and
licensed per-outlet). Instead, [`/api/og/[slug]`](../src/app/api/og/%5Bslug%5D/route.tsx) renders
an original branded "scoreboard card" per article — team names/score, category, and site
branding — server-side, from our own data. No third-party images involved.

Posting now goes through the `/{page-id}/photos` Graph API endpoint with that generated
image, rather than a plain text `/feed` post.

## Link handling: comment, not caption

You asked to remove links from the post body — that also happens to match Meta's own feed
ranking behavior, which suppresses reach on posts containing an outbound link in the caption.
`postArticleToFacebook` now:

1. Posts the image + caption with **no link in the post body**, just "link in the comments 👇".
2. Immediately adds a comment on that post containing the article URL.

This keeps the post itself link-free for reach purposes while the link is still one tap away
for anyone interested.

## Cadence

- **Trending match** (`trendingScore > 0`): post immediately on approval (current behavior,
  unchanged — `approveArticle` still calls `postArticleToFacebook`).
- **Everything else**: current code posts every approved article immediately. Worth deciding
  before going live: do you want *every* approved article posted, or should low-trending
  articles queue and post on a fixed cadence (e.g. max 4-6 posts/day) so the Page doesn't look
  like a bot feed? Happy to add a simple queue + cron-driven throttle if you want that —
  didn't build it since it's a product decision, not a technical one.
